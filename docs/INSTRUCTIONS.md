# AstroBookings — Usage Instructions

> **English** · [Español](#guía-de-uso-de-astrobookings)

AstroBookings is a backend API to manage rocket launch bookings. This guide explains how to install, configure, run, test, and consume it.

## Requirements

- Node.js 24 (LTS), as defined in `AGENTS.md`.
- npm (included with Node.js).

## Installation

```bash
npm install
```

## Configuration

Copy the example environment file and adjust the values if needed:

```bash
cp .env.example .env
```

| Variable | Default | Description |
|---|---|---|
| `PORT` | `3000` | Port where the HTTP server listens. |
| `NODE_ENV` | `development` | Environment name, reported by the health endpoint. |

Variables are read from `.env` by `src/config/env.ts`. If a variable is missing, its default is used.

## Running

| Command | Description |
|---|---|
| `npm run dev` | Starts the server in development mode with automatic reload (`tsx watch`). |
| `npm run build` | Compiles TypeScript to `dist/`. |
| `npm start` | Runs the compiled version from `dist/`. Run `npm run build` first. |

After starting, the server listens on `http://localhost:<PORT>`. The API is mounted under `/api`.

## Testing

```bash
npm test
```

Runs the Jest suite, including the end-to-end tests in `tests/`.

## API Reference

Base URL: `http://localhost:3000/api`

### Health

| Method | Path | Description |
|---|---|---|
| `GET` | `/api/health` | Returns service status, uptime, environment, Node version, and memory usage. |

```bash
curl http://localhost:3000/api/health
```

### Rockets

| Method | Path | Success | Description |
|---|---|---|---|
| `GET` | `/api/rockets` | 200 | List all rockets. |
| `GET` | `/api/rockets/:id` | 200 | Get one rocket by id. |
| `POST` | `/api/rockets` | 201 | Create a rocket. |
| `PUT` | `/api/rockets/:id` | 200 | Update a rocket's name, range, and/or capacity. |
| `DELETE` | `/api/rockets/:id` | 200 | Delete a rocket. |

**Rocket fields**

| Field | Rules |
|---|---|
| `name` | Required. Non-empty string. |
| `range` | One of: `suborbital`, `orbital`, `moon`, `mars`. |
| `capacity` | Integer from 1 to 10. |

The `id` is generated by the server (UUID) and cannot be set by the client.

**Create a rocket**

```bash
curl -X POST http://localhost:3000/api/rockets \
  -H "Content-Type: application/json" \
  -d '{"name": "Falcon 9", "range": "orbital", "capacity": 7}'
```

Response (201):

```json
{
  "id": "<generated-uuid>",
  "name": "Falcon 9",
  "range": "orbital",
  "capacity": 7
}
```

**List rockets**

```bash
curl http://localhost:3000/api/rockets
```

**Get a rocket**

```bash
curl http://localhost:3000/api/rockets/<id>
```

**Update a rocket**

Send only the fields to change. Validation rules still apply to the fields sent.

```bash
curl -X PUT http://localhost:3000/api/rockets/<id> \
  -H "Content-Type: application/json" \
  -d '{"capacity": 9}'
```

**Delete a rocket**

```bash
curl -X DELETE http://localhost:3000/api/rockets/<id>
```

Response (200):

```json
{
  "message": "Rocket deleted successfully"
}
```

## Error Responses

All errors return a JSON body with an `error` message:

```json
{
  "error": "Rocket capacity must be an integer between 1 and 10"
}
```

| Status | When |
|---|---|
| 400 | Validation fails: missing name, invalid range, or capacity outside 1–10. |
| 404 | No rocket exists with the given id. |
| 500 | Unexpected server error, including a malformed JSON body. The message is hidden: `Internal server error`. |

## Logging

Each log line includes an ISO timestamp and a level: `INFO`, `WARN`, `ERROR`, or `DEBUG`. HTTP requests are logged by the request logger. Example output:

```text
[2026-10-29T14:00:00.000Z] [INFO] POST /api/rockets 201 12ms
[2026-10-29T14:00:00.000Z] [INFO] Rocket registered: Falcon 9 (a1b2c3...)
```

## Planned Features

The following are not yet available. See [PRD.md](./PRD.md) for details:

- Launch scheduling and lifecycle.
- Customer identification.
- Seat bookings with capacity checks.
- Simulated payments.

## Troubleshooting

| Problem | Solution |
|---|---|
| `EADDRINUSE` on startup | Another process uses the port. Change `PORT` in `.env` or stop the other process. |
| `npm start` fails with missing file | Run `npm run build` first to generate `dist/`. |
| `400` on create or update | Check the rules in the Rocket fields table. |
| `500` with a valid-looking request | Check that the body is valid JSON and sent with `Content-Type: application/json`. Malformed JSON currently returns 500, not 400. Check the server log for the parse error. |
| `404` on get, update, or delete | The id does not exist. Run `GET /api/rockets` to list valid ids. |
| Data disappears after restart | Expected. Storage is in memory only. |

# Guía de uso de AstroBookings

> [English](#astrobookings--usage-instructions) · **Español**

AstroBookings es una API backend para gestionar reservas de lanzamientos de cohetes. Esta guía explica cómo instalarla, configurarla, ejecutarla, probarla y consumirla.

## Requisitos

- Node.js 24 (LTS), según se define en `AGENTS.md`.
- npm (incluido con Node.js).

## Instalación

```bash
npm install
```

## Configuración

Copia el archivo de variables de entorno de ejemplo y ajusta los valores si es necesario:

```bash
cp .env.example .env
```

| Variable | Valor por defecto | Descripción |
|---|---|---|
| `PORT` | `3000` | Puerto donde escucha el servidor HTTP. |
| `NODE_ENV` | `development` | Nombre del entorno, reportado por el endpoint de salud. |

`src/config/env.ts` lee las variables desde `.env`. Si una variable falta, se usa su valor por defecto.

## Ejecución

| Comando | Descripción |
|---|---|
| `npm run dev` | Inicia el servidor en modo desarrollo con recarga automática (`tsx watch`). |
| `npm run build` | Compila TypeScript a `dist/`. |
| `npm start` | Ejecuta la versión compilada desde `dist/`. Ejecuta antes `npm run build`. |

Al iniciar, el servidor escucha en `http://localhost:<PORT>`. La API está montada bajo `/api`.

## Pruebas

```bash
npm test
```

Ejecuta la suite de Jest, incluidas las pruebas end-to-end de `tests/`.

## Referencia de la API

URL base: `http://localhost:3000/api`

### Salud

| Método | Ruta | Descripción |
|---|---|---|
| `GET` | `/api/health` | Devuelve el estado del servicio, tiempo de actividad, entorno, versión de Node y uso de memoria. |

### Cohetes

**Campos del cohete**

| Campo | Reglas |
|---|---|
| `name` | Obligatorio. Cadena no vacía. |
| `range` | Uno de: `suborbital`, `orbital`, `moon`, `mars`. |

**Crear un cohete**

```bash
curl -X POST http://localhost:3000/api/rockets \

  -d '{"name": "Falcon 9", "range": "orbital", "capacity": 7}'
```

Respuesta (201):

```json
{
  "id": "<uuid-generado>",
  "name": "Falcon 9",
  "range": "orbital",
  "capacity": 7
```

**Listar cohetes**

```bash
curl http://localhost:3000/api/rockets
```

**Actualizar un cohete**

Envía solo los campos que quieres cambiar. Las reglas de validación se aplican a los campos enviados.

```bash
curl -X PUT http://localhost:3000/api/rockets/<id> \
  -H "Content-Type: application/json" \
  -d '{"capacity": 9}'
```

**Eliminar un cohete**

```bash
curl -X DELETE http://localhost:3000/api/rockets/<id>
```

Respuesta (200):

```json
{
  "message": "Rocket deleted successfully"
```

## Respuestas de error

Todos los errores devuelven un cuerpo JSON con un mensaje en `error`:

```json
{
  "error": "Rocket capacity must be an integer between 1 and 10"
}
```

| Estado | Cuándo |
|---|---|
| 400 | Falla la validación: falta el nombre, el alcance no es válido o la capacidad está fuera de 1–10. |
| 404 | No existe un cohete con el id indicado. |
| 500 | Error inesperado del servidor, incluido un cuerpo JSON malformado. El mensaje se oculta: `Internal server error`. |

## Logging

Cada línea de log incluye un timestamp ISO y un nivel: `INFO`, `WARN`, `ERROR` o `DEBUG`. El logger de peticiones registra las solicitudes HTTP. Ejemplo de salida:

```text
[2026-10-29T14:00:00.000Z] [INFO] POST /api/rockets 201 12ms
[2026-10-29T14:00:00.000Z] [INFO] Rocket registered: Falcon 9 (a1b2c3...)
```

## Solución de problemas

| Problema | Solución |
|---|---|
| `EADDRINUSE` al iniciar | Otro proceso usa el puerto. Cambia `PORT` en `.env` o detén el otro proceso. |
| `npm start` falla por archivo faltante | Ejecuta `npm run build` primero para generar `dist/`. |
| `400` al crear o actualizar | Revisa las reglas de la tabla de campos del cohete. |
| `500` con una petición aparentemente válida | Verifica que el cuerpo sea JSON válido y que se envíe con `Content-Type: application/json`. Un JSON malformado devuelve 500, no 400. Revisa el log del servidor para ver el error de parseo. |
| `404` al obtener, actualizar o eliminar | El id no existe. Ejecuta `GET /api/rockets` para listar ids válidos. |
| Los datos desaparecen al reiniciar | Es lo esperado. El almacenamiento es solo en memoria. |
